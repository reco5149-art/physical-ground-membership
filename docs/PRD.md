# PRD: 피지컬그라운드 회원관리 앱 (MVP)

| 항목 | 내용 |
|---|---|
| 문서 상태 | Draft v1.0 |
| 작성일 | 2026-09-08 |
| 제품명 | 피지컬그라운드 회원관리 앱 (가칭) |
| 대상 | 피지컬그라운드 운영 직원(관리자) |

## 1. 배경 및 문제 정의

피지컬그라운드는 현재 회원 정보, 회원권 현황, 출석 이력을 엑셀/수기 등 비체계적인 방식으로 관리하고 있다고 가정한다. 이로 인해 다음과 같은 문제가 발생한다.

- 회원 정보가 여러 곳에 흩어져 있어 조회/수정이 번거롭다.
- 회원권 만료 시점을 놓쳐 회원 응대가 늦어진다.
- 출석 이력이 체계적으로 쌓이지 않아 운영 지표(재등록률, 이용 빈도 등)를 파악하기 어렵다.

이를 해결하기 위해, 웹 기반의 회원관리 앱을 구축하여 직원이 언제 어디서나 회원 정보/회원권/출석을 한 곳에서 관리할 수 있도록 한다.

## 2. 목표

1. 회원 정보와 회원권 상태를 한 화면에서 관리한다.
2. 회원권 만료(임박) 회원을 놓치지 않고 파악한다.
3. 출석 체크를 빠르고 간편하게 처리하고, 이력을 자동으로 누적한다.
4. 가입된 직원 계정만 접근 가능하도록 인증을 적용한다.

### 성공 지표 (KPI, 참고용)

- 회원 조회/등록에 걸리는 시간 단축 (엑셀 대비)
- 회원권 만료 회원 누락률 0에 근접
- 출석 체크 소요 시간 1건당 10초 이내

## 3. 대상 사용자

- **주 사용자**: 피지컬그라운드 운영 직원(관리자). 로그인 후 회원 등록, 회원권 부여, 출석 체크, 현황 조회를 수행한다.
- **비대상(이번 MVP 제외)**: 회원 본인. 회원이 앱에 직접 로그인해 본인 정보를 조회하는 기능은 이번 범위에 포함하지 않는다.

인증이 필요한 이유는 회원의 개인정보(이름, 연락처, 생년월일 등)를 다루기 때문이며, **가입 절차를 거친 직원 계정만 앱에 접근**할 수 있어야 한다.

## 4. 범위

### 4.1 In Scope (MVP)

| 영역 | 기능 | 우선순위 |
|---|---|---|
| 인증 | 직원 회원가입(이메일/비밀번호) | P0 |
| 인증 | 로그인 / 로그아웃 | P0 |
| 인증 | 비로그인 사용자의 모든 페이지 접근 차단 | P0 |
| 회원 관리 | 회원 등록 (이름, 연락처, 생년월일, 성별, 메모) | P0 |
| 회원 관리 | 회원 목록 조회 및 이름/연락처 검색 | P0 |
| 회원 관리 | 회원 상세 조회 / 정보 수정 / 삭제(비활성화) | P0 |
| 회원권 관리 | 회원권 등록 (기간제: 시작일~종료일 / 횟수제: 총 횟수) | P0 |
| 회원권 관리 | 회원권 상태 자동 계산 (정상 / 만료임박 / 만료) | P0 |
| 회원권 관리 | 회원권 갱신(재등록) | P1 |
| 출석 체크 | 회원 검색 후 출석 체크인 | P0 |
| 출석 체크 | 출석 시 횟수제 회원권 잔여 횟수 자동 차감 | P0 |
| 출석 체크 | 회원별 출석 이력 조회 | P1 |
| 대시보드 | 오늘 출석 인원 수 | P1 |
| 대시보드 | 회원권 만료임박(7일 이내)/만료 회원 리스트 | P1 |
| 대시보드 | 전체 회원 수, 활성 회원권 수 등 요약 지표 | P2 |

### 4.2 Out of Scope (이번 MVP 제외)

- 구독/결제 시스템 (신용카드 결제, 정기결제 등)
- 회원 본인 로그인 및 셀프 서비스 (앱/웹으로 본인 출석·잔여횟수 조회)
- SMS/알림톡 등 자동 알림 발송 (대시보드 내 리스트 확인으로 대체)
- 수업/PT 세션 예약 및 캘린더 기능
- 다지점(멀티 브랜치) 지원 및 지점 간 데이터 분리
- 직원 권한 세분화(마스터/일반 등 역할 구분) — 로그인한 직원은 모두 동일 권한

> Out of Scope 항목은 MVP 이후 로드맵에서 우선순위에 따라 추가 논의한다.

## 5. 핵심 사용자 스토리

1. **직원으로서**, 이메일과 비밀번호로 가입하고 로그인해서 앱에 접근하고 싶다.
2. **직원으로서**, 신규 회원이 방문하면 이름/연락처 등 기본 정보를 빠르게 등록하고 싶다.
3. **직원으로서**, 회원에게 회원권(기간제 또는 횟수제)을 부여하고 싶다.
4. **직원으로서**, 회원이 방문하면 이름으로 검색해서 즉시 출석 체크하고 싶다.
5. **직원으로서**, 출석 체크 시 횟수제 회원의 잔여 횟수가 자동으로 줄어들어 별도 계산이 필요 없기를 원한다.
6. **직원으로서**, 회원권이 곧 만료되거나 이미 만료된 회원 목록을 한눈에 보고 싶다.
7. **직원으로서**, 특정 회원의 과거 출석 이력을 조회하고 싶다.

## 6. 화면 정의

| 화면 | 설명 |
|---|---|
| 로그인 | 이메일/비밀번호 로그인, 회원가입 화면으로 이동 링크 |
| 회원가입 | 이메일/비밀번호(+확인)로 직원 계정 생성 |
| 대시보드(홈) | 오늘 출석 수, 만료임박/만료 회원 리스트, 요약 지표 |
| 회원 목록 | 검색/필터, 회원권 상태 뱃지 표시, 신규 등록 버튼 |
| 회원 등록/수정 | 이름, 연락처, 생년월일, 성별, 메모 입력 폼 |
| 회원 상세 | 기본 정보 + 보유 회원권 현황 + 출석 이력 |
| 회원권 등록 | 회원권 종류(기간제/횟수제) 선택 후 조건 입력 |
| 출석 체크 | 회원 검색 → 선택 → 체크인 버튼 (당일 중복 체크 방지) |

## 7. 데이터 항목 (개략)

- **회원(Member)**: 이름, 연락처, 생년월일, 성별, 메모, 등록일, 상태(활성/비활성)
- **회원권(Membership)**: 회원 ID, 종류(기간제/횟수제), 시작일, 종료일(기간제), 총 횟수/잔여 횟수(횟수제), 상태
- **출석(Attendance)**: 회원 ID, 체크인 일시, 처리한 직원

## 8. 비기능 요구사항

- 반응형 웹: 데스크탑 기준으로 설계하되 태블릿/모바일에서도 주요 기능(검색, 출석 체크) 사용 가능해야 한다.
- 보안: 회원 개인정보는 로그인한 직원만 열람 가능해야 하며, 비로그인 접근은 차단한다.
- 가용성: 특별한 SLA 요구는 없으나, 영업시간(출석 체크가 몰리는 시간대) 중 응답 지연이 없어야 한다.
- 데이터 규모 가정: 회원 수 최대 수천 명, 동시 접속 직원 수 명 이내.

## 9. 제약사항 및 가정

- 결제 기능은 이번 범위에서 제외한다.
- 단일 지점 운영을 가정한다.
- 로그인한 모든 직원은 동일한 권한을 가진다 (역할 구분 없음).
- 회원 데이터는 직접 입력을 기준으로 하며, 기존 엑셀 데이터 마이그레이션 여부는 별도 논의한다.

## 10. 향후 로드맵 (참고)

1. 구독 결제 연동 (회원권 결제, 자동 갱신)
2. 회원 본인용 셀프 서비스 화면
3. SMS/알림톡 자동 발송 (만료 임박 알림)
4. 수업/PT 예약 캘린더
5. 다지점 지원 및 직원 권한 세분화
