### 주요 구현 결정

1. **집계는 순수 함수로 분리**: 화면(`page.tsx`)은 DB에서 값을 읽어 `summarizeMembers`에 넘기고 결과를 그리기만 한다. "알고 있는 입력 → 기대 숫자"를 단위 테스트로 검산하기 위함(기존 모듈들과 동일한 방식).
2. **대표 회원권 규칙 재사용**: 회원이 여러 회원권을 가지면 `pickPrimaryMembership`(종료일이 가장 늦은 것)으로 대표를 고른 뒤 상태를 판정한다. 그래서 "옛 만료 회원권 + 갱신한 정상 회원권"을 가진 회원은 **만료 목록에 뜨지 않는다**(정상으로 분류). 회원 목록 화면(`members/page.tsx`)과 동일한 판정.
3. **오늘 출석 수는 KST 기준 UTC 구간으로 카운트**: `attendances.checked_in_at`은 UTC이므로 `seoulDayRange(todayInSeoul())`로 KST "오늘"에 해당하는 UTC 구간을 만들어 `gte/lt`로 센다. UTC 기준으로 세면 시간대 버그가 생긴다(Module 6 결정 사항 그대로 재사용).
4. **활성 회원 수는 권위 있는 count 쿼리**로 별도 조회(`count: 'exact', head: true`). 목록 카드용으로 가져온 회원 배열 길이와 분리했다.
5. **유효 회원권 = 정상 + 만료임박** 합계(`validMembershipCount`). 만료·회원권없음은 제외.
6. **응대 목록은 활성 회원만** 대상으로 한다(비활성 회원은 응대 필요 대상이 아님). 회원 조회에 `.eq('status','active').limit(1000)` 적용.
7. **경로 별칭(`@/`) vs 테스트 러너 충돌 해결**: `summary.ts`는 다른 소스 파일처럼 `@/lib/...` 별칭으로 import 한다(Next 빌드는 tsconfig `paths`로 해석). 하지만 `node --test`는 tsconfig paths를 모른다. 소스가 소스를 import 하는 첫 사례라 이 문제가 처음 드러났다.
   - `.ts` 확장자 상대경로로 바꾸면 `node --test`는 통과하지만 Next 빌드 타입체크가 **TS5097**로 실패한다(base tsconfig는 `allowImportingTsExtensions` 미설정).
   - 그래서 소스는 별칭을 유지하고, **테스트 런타임에만** `@/` → 프로젝트 루트로 매핑하는 작은 resolve 훅(`scripts/alias-loader.mjs`)을 붙였다. 타입 검증은 `tsconfig.test.json`의 `paths`가 이미 처리한다. 이로써 "소스=별칭 / 테스트=상대 .ts"라는 기존 설계 원칙을 유지한 채 둘 다 통과한다.
   - **다음에 소스 파일끼리 import 할 때도 `@/` 별칭을 그대로 쓰면 된다** — 훅이 자동 처리한다.
