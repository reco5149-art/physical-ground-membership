### 주요 구현 결정

1. **가격은 서버에서 다시 읽는다**: 폼은 `plan_code`만 전송하고, 이름·가격·기간은 서버의 상수표(`findPlan`)에서 조회한다. 클라이언트가 보낸 가격을 신뢰하면 폼 조작으로 임의 금액 등록이 가능하기 때문이다. 존재하지 않는 코드는 거부한다.
2. **이름·가격 스냅샷 저장**: 요금이 인상되어도 과거 판매 기록은 당시 값을 유지해야 하므로 `plan_name`/`price`를 행에 함께 저장한다.
3. **종료일 자동 계산**: `시작일 + N개월 - 1일`. 말일 보정 포함 — `1/31 + 1개월`은 2월에 31일이 없으므로 **2월 말일(2/28, 윤년 2/29)까지 인정**한다(회원에게 불리하지 않게).
4. **종료일 당일은 아직 유효**: `end_date === 오늘`이면 만료가 아니라 만료임박으로 본다.
5. **대표 회원권**: 갱신·재등록으로 회원이 여러 회원권을 가질 수 있어, **종료일이 가장 늦은 것**을 대표로 삼는다(`pickPrimaryMembership`).
6. **목록 N+1 방지**: 회원 목록에서 회원권을 회원별로 각각 조회하지 않고 `in()` 한 번으로 가져와 메모리에서 매칭한다.
7. **요금제는 코드 상수**: 4종 고정이라 DB 테이블 + 관리 화면 대신 상수로 관리. 상품이 늘면 테이블로 승격 검토(TECH_SPEC 4.3절에 명시).

## 다음 모듈이 알아야 할 것

1. **⚠️ Module 6에서 반드시 구현할 것 — 주간 횟수 경고**
   - 이번 주(월~일) 출석 수가 회원권의 `sessions_per_week` 이상이면 **경고를 표시하되 체크인은 허용**한다. (사용자 확정 정책)
   - 주 시작 기준은 **월요일**, 날짜는 한국 시간(`todayInSeoul()`) 기준.
2. **현재 요금제에 횟수제가 없다**: `total_count`/`remaining_count` 컬럼은 남아 있지만 사용하지 않는다. Module 6의 "횟수 차감" 로직은 **해당 없음**이며, 대신 위 주간 횟수 경고를 구현한다.
3. **바로 쓸 수 있는 것**
   - `lib/memberships/status.ts`의 `pickPrimaryMembership`·`describeMembership`으로 회원의 현재 회원권 상태를 얻을 수 있다.
   - 출석 화면에서 회원 검색은 Module 4의 `members` 조회 패턴(`or(name.ilike, phone.ilike)` + 검색어 살균)을 재사용할 것.
   - 회원 상세 페이지 하단에 "출석 이력은 Module 6에서 추가" 안내 박스가 자리를 잡아두었다.
4. **테스트 데이터**: `홍길동(수정됨)`에 회원권 2건(3개월 주5회 정상 / 1개월 주3회 만료), `박지은`은 회원권 없음. Module 6 테스트에 그대로 활용 가능.
5. **미구현**: 회원권 "갱신" 전용 UI는 없다. 새 회원권을 추가하면 종료일이 더 늦은 것이 자동으로 대표가 되므로 사실상 갱신으로 동작한다(PRD P1 요구사항 충족).
