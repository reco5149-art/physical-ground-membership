## 1. 백업 (Backup)

- **DB**: Supabase 무료 플랜은 Point-in-Time Recovery(PITR)가 없다. 최소한의 방어로 **정기 수동 백업**을 둔다.
  - 방법: Supabase 대시보드 → Database → Backups에서 제공되는 다운로드, 또는 로컬에서
    ```bash
    pg_dump "postgresql://postgres:[비밀번호]@[프로젝트].supabase.co:5432/postgres" > backup_$(date +%Y%m%d).sql
    ```
    (연결 문자열은 대시보드 → Project Settings → Database. 비밀번호는 문서에 남기지 말 것.)
  - 주기: 〔확정 필요 — 권장: 주 1회, 회원/결제 데이터가 늘면 일 1회〕
  - 보관 위치: 〔확정 필요 — 예: 담당자 PC + 클라우드 드라이브 이중 보관〕
  - 복구 리허설: 〔확정 필요 — 백업이 실제로 복원되는지 분기 1회 확인〕
- **유료 전환 시**: Supabase Pro의 자동 일일 백업 + PITR로 승격하면 수동 백업 부담이 사라진다. 회원 데이터가 "잃으면 안 되는" 규모가 되는 시점이 전환 신호(8.8절과 연동).

## 2. 로그·모니터링 (Logs & Monitoring)

- **어디서 보는가**
  - Supabase 대시보드 → Logs: Auth / Postgres / API 로그 (로그인 실패, RLS 거부, 쿼리 오류)
  - Vercel 대시보드 → 프로젝트 → Deployments / Logs: 빌드 실패, Server Action·Route 런타임 오류
- **누가·언제 확인하는가**: 〔확정 필요 — 예: 담당자가 주 1회 대시보드 점검, 배포 직후 1회 확인〕
- **이상 징후 예시**: Auth 로그에 특정 IP의 로그인 실패 급증(무차별 시도 → 앱 rate limit 동작 확인), API 로그에 RLS 거부 다발(권한/정책 점검), Vercel 함수 오류율 상승.
- **개선 여지**: 규모가 커지면 에러 트래킹 도구(Sentry 등)를 도입해 "누가 알아채는가"를 사람 확인에서 자동 알림으로 바꾼다. (현재 MVP는 대시보드 수동 확인)

## 3. 개인정보 보관·파기 정책 (Privacy)

- **수집 항목**: 이름, 연락처(휴대폰), 생년월일(선택), 성별(선택), 메모. 로그인 계정(직원)의 이메일.
- **이용 목적**: 회원 식별, 회원권/출석 관리, 만료 안내 등 운영 목적에 한정.
- **보관 기간**: 〔확정 필요 — 예: 회원 자격 종료(탈퇴/장기 미이용) 후 N개월 보관 뒤 파기〕
- **탈퇴·삭제 요청 처리**
  - 현재 회원 삭제는 **소프트 삭제**(`status = 'inactive'`)로 동작한다(하드 삭제 아님). 이력(출석·회원권)은 정산/분쟁 대비로 남는다.
  - 완전 파기(하드 삭제) 요청 시 처리 절차: 〔확정 필요 — 누가 승인하고, 어떤 테이블을 어떤 순서로 지우는지. `attendances`·`memberships`가 `members`를 FK로 참조하므로 삭제 순서 주의〕
- **접근 통제**: DB는 RLS로 로그인한 직원만 접근 가능(anon 키로는 조회 불가). 직원 계정은 신뢰된 인원에게만 발급한다.
- **주의**: 개인정보를 로그·URL 쿼리스트링·외부 서비스에 남기지 않는다(검색어는 GET 쿼리로 전달되므로, 로그에 회원 검색 파라미터가 과도하게 쌓이지 않는지 주기적으로 확인).

## 4. 무료 티어 한계와 전환 계획 (Free-Tier → Paid)

| 서비스 | 무료 한계 | 전환 신호 | 전환 대상 |
|---|---|---|---|
| Supabase | 미사용 시 프로젝트 pause(콜드스타트 지연), 백업/PITR 제한 | 실사용 시작(매일 접속), 회원 데이터 유실 위험 | Supabase Pro |
| Vercel | 함수 실행시간·대역폭 한도 | 트래픽/사용량 경고 발생 | Vercel Pro |
| 이메일(SMTP) | 무료 티어 월 발송 한도(예: Resend 월 3,000통) | 가입/알림 메일 발송량이 한도에 근접 | 유료 플랜 또는 발송 전용 서비스 |

- 원칙: "무료로 영원히"가 아니라 **"MVP 검증까지 무료 → 실사용 규모 확인 시 유료/전용 인프라 전환"**.
- 특히 **Supabase 무료 pause**는 실사용에 치명적이므로(첫 방문자가 콜드스타트 지연을 겪음), 실제 오픈과 동시에 Pro 전환을 우선 검토한다.
